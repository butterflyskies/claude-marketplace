# Loading and Following Are Different Organs

A hook closes *didn't know -> knew*. A gate closes *knew -> did*.

Two different failure modes. Building one does not buy the other — and only one of them is structure.

**Loading failure** — the construct never had the fact. Addressed by injecting state before the model gets a turn: a SessionStart hook that reloads memory deterministically, rather than a checklist the instance reads and chooses to follow.

**Following failure** — the construct had the fact, had read it, agreed with it, and did the other thing anyway. Addressed only by something acting at the point of output: a blocklist at the lips rather than a prompt asking for restraint.

## Only the gate is structure

A hook makes *delivery* deterministic; everything it delivers is still a wish. **A memory that arrives on time is an intention that arrived on time.** Nothing in the loading path is structure. The gate is the only structure, because it is the only part that *acts* rather than *informs*.

## Why this matters for boot design

A boot checklist is **intention with good ergonomics**. If a phase is skipped, nothing stops it, nothing notices, and the instance can't tell afterward. The genuinely structural parts of any boot are the ones that **leave artifacts outside the agent**.

Corollary: **make each phase emit a receipt**, so a skipped phase becomes visible. The missing check-in *is* the check-in.

**Build both. They're different organs. Only one of them can stop you.**
